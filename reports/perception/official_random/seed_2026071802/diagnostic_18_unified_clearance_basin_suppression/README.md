# diagnostic_18：统一净空后真实房间红球候选与横移死区诊断

本目录保存官方 `auto.sh` 固定 `SEED=2026071802` 三层随机复杂楼宇中的真实运行
记录，不是受控专项成绩，也不是完整官方闭环。运行期只使用公开 RGB、深度、相机
内参、雷达、IMU、合法 Cartographer SLAM、公开门控服务和 `/hw/cmd_vel`；未读取
场景布局、危险源真值或 Gazebo ground truth。

## 运行结论

- 代码版本：`9a8c806a566b737ad5f90087383c06c43c5bb425`。
- 全局 A* 和局部安全门禁统一使用 0.45 m 净空；同一不可达盆地在单轮规划中
  只计一次失败。运行中没有再出现上一轮的“规划可通行、执行持续归零”卡死，
  也没有同一时刻失败次数从 1 瞬间跳到 2。
- 机器人自主选择 18 个前沿、真实到达 4 个，沿复杂楼内走廊推进到合法 SLAM
  `odom` 约 `(16.99,-1.34)`；保存 2082 帧 RGB 记录、312 条合法 SLAM 轨迹和
  `663 × 382 @ 0.05 m` 地图。
- 在真实房间墙角首次持续发现一个红色圆形候选：634 帧含候选，其中 580 帧完成
  RGB-D/TF 三维定位，平均置信度 0.9466；轨迹 `1` 最终保持
  `tentative / collecting_views`，547 条合格观测仍只有 1 个独立视角。
- 系统先执行右转把贴边候选移入画面，再请求向左横移。ROS2 `/hw/cmd_vel` 和
  ROS1 `/cmd_vel` 均实测收到 `linear.y=0.15 m/s`，但 36.899 仿真秒内合法
  SLAM 位移仅约 `0.00011 m`，说明指令低于官方 A1 RL 控制器的有效横移响应。
- 首帧使用 `untracked:1`、建轨后使用 `1`，旧逻辑把两者分开计数，亦会绕过单目标
  最大复查次数。下一代码版本已统一目标 ID，并把横移/前进复查速度提高到官方
  控制器实测有效量级。
- 本轮在确认阻断后主动中止。`summary.json` 明确记录
  `mission_completed=false`、`confirmed_hazard_count=0`；没有生成或伪造
  `detected_danger.json`。

## 感知与导航 A/B 结论

与 diagnostic_17 相比，统一净空显著提高了实际覆盖距离，并首次把传感器带到
真实复杂房间中的红色候选视野。单帧颜色和轮廓不足以证明它是红球，当前坚持不把
候选写入正式结果；这正验证了“看到圆形先怀疑圆柱/圆锥端面，再主动侧视”的门禁
正在生效。当前确定性阻断已收敛为官方 A1 的平移指令死区，而不是检测器漏掉目标。
