# 官方 ROS1 隔离运动探测记录

日期：2026-07-13

## 目的与隔离边界

为避免干扰正在运行的共享官方 SimEnv，本次从其挂载的已编译工作区复制出独立副本，并以 Docker
默认隔离网络启动 ROS1 Noetic + Gazebo Classic headless 容器。容器内生成了一颗临时红球，运行
当前感知节点；试验结束后不将其结果并入五类正式证据。

## 已验证

- 隔离容器内 RGB、深度、CameraInfo、Gazebo、`junior_ctrl`、`/joy` 与 `/cmd_vel` 话题都能出现。
- 当前感知节点在该容器真实 RGB-D 流中检出受控红球并形成单视角 tentative 轨迹。
- 控制器接受官方键盘序列 `2 -> 6`（固定站立 -> RL）。在 RL 后发送五次左向键输入，
  `/Odometry_gazebo` 的平面位置从约 `(-0.496, -2.797)` 变为 `(-0.411, -2.810)`，实际位移约
  **0.085 m**。

## 发现的阻塞

1. 本轮运行时 `rosnode info /junior_ctrl` 未显示 `/cmd_vel` 订阅，`rostopic info /cmd_vel` 只有
   `/unitree_gazebo_servo` 订阅；直接发布 `/cmd_vel` 未产生可用的受控机器人位移。虽然源码中的
   RL 状态包含回调，当前二进制运行行为不能据此假设接口可用。
2. 键盘输入能产生位移，但当前短时探测的姿态/速度仍明显不稳定，不能安全保证“横移后停稳、相机
   保持目标在视场、TF 可连续定位”。因此不能用该探测拼出 25° 视差，更不能写成多视角确认成功。
3. 隔离工作区自带的 `auto_noetic_headless.sh` 在控制器段后存在一个多余 `fi`；仅在隔离副本中
   移除了它以启动测试，未改动共享官方工作区。

## 结论

本次证明了“独立官方 ROS1 容器 + 真实传感器 + 机器狗实际位移”的测试环境可启动，也暴露了当前
控制接口/步态稳定性问题。正式五类中的连续多视角、部分球主动复查、复杂定位和全屋视角策略 A/B
仍必须等平台组提供稳定、可由导航节点控制的运动接口后重跑。临时红球、临时节点和隔离容器不作为
正式成绩素材。
