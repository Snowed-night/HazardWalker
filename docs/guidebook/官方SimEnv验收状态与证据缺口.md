# 官方 SimEnv 验收状态与证据缺口

更新时间：2026-07-23。本文只根据仓库中的测试记录、报告和代码静态审计汇总；未在本轮独占会话中重新启动官方环境。除非下表要求的原始证据齐全，不得宣称整组或整机闭环完成。

## 共同验收规则

- 只使用官方允许的 RGB、深度、点云、内参、雷达、公开服务和自建合法 SLAM 位姿；运行期不得读取 `danger_truth.json`、世界文件、布局元数据或硬编码目标位置。
- 每轮须记录 SEED、Git 版本、启动参数、话题/TF、原图或原始传感器片段、输出、测试表和失败边界。
- “节点存在”“有消息”“候选框出现”均不是任务成功；控制、探索、确认、定位和返航分别给出证据。

## 当前不得宣称的结论

- 不得宣称已完成未知多层楼宇自主探索或官方满分任务。
- 不得以受控夹具、局部烟测、固定航点、Gazebo 派生位姿或离线单测宣称官方随机场景通过。
- 不得将黄色 `reobserve` 候选、单帧圆形或未完成侧视验证的对象计为红球危险源。
- 不得把历史 ROS2 Harmonic、旧双栈或旧适配器作为当前官方接入证据。

## 最小正式闭环批次

一次可进入成绩讨论的批次至少包含：独占会话证明、固定 SEED、最新代码版本、合法位姿来源、官方原始 RGB-D/雷达、完整机器人轨迹、候选与确认时间线、最终 `detected_danger.json`、返航证据、离线评分记录及所有失败原因。成果位置统一为 `reports/<group>/`，格式遵循 [测试记录规范](测试记录规范.md)。
