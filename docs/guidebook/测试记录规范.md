# 测试记录规范

适用范围：平台、导航、感知、决策、集成测试与正式联调。本文是仓库内唯一的测试记录填写规范和字段模板。

## 1. 何时记录

每次离线回归、仿真、官方平台运行、截图/视频采集、失败复现或正式联调后都必须记录；失败记录与通过记录同等重要。不得把候选检出、话题存在或进程启动写成任务完成。

## 2. 存放与命名

```text
reports/<group>/test_records/<YYYYMMDD_实验类别或批次>/
├─ testing_record_<group>.csv
├─ testing_record_<group>.json
└─ README.md                 # 有运行环境或失败边界时必须提供
```

感知专项实验的原始图、标注图、`summary.json`、SEED、启动参数、Git 版本及失败说明同时放在对应的 `reports/perception/` 实验目录；测试记录只引用该目录，不复制素材。

## 3. 所有组必填字段

| 字段 | 要求 |
|---|---|
| 日期与执行人 | 测试实际执行日期和人员 |
| 分组与 Git 版本 | 分支、完整或短提交 ID、是否有未提交改动 |
| 命令与参数 | 可复现的完整启动/测试命令，包含 SEED、配置覆盖和输入来源 |
| 环境 | 本机/主力机/官方 SimEnv、ROS 版本、是否 headless、设备或容器标识 |
| 输入与输出 | 话题、文件或场景；输出目录及结果文件 |
| 结果 | 通过、失败或部分通过；不得只写“成功” |
| 耗时与性能 | 总耗时；有数据时写帧率、延迟、资源或处理时间 |
| 失败边界 | 失败条件、关键日志、是否可复现、后续处理人/计划 |

## 4. 专项指标

| 组别 | 至少记录 |
|---|---|
| 感知 | 目标数、检出/漏检/虚警、确认数、定位误差、单帧耗时或 FPS、多帧确认率；真值不可作为运行期输入 |
| 导航 | 覆盖范围、轨迹/里程计、探索与返航耗时、碰撞/卡滞、地图与定位来源 |
| 平台 | 传感器话题/内参/TF、控制与停止证据、发布者/订阅者、进程清理和异常恢复 |
| 决策 | 状态转换、候选到确认的门控、重观察请求、超时/失败处理与结果输出 |
| 集成测试 | 参与模块、接口版本、端到端结果、未覆盖边界和阻塞条件 |

没有真值、性能数据或某项条件时，填写“未测”及原因；禁止填 0 或通过来伪造结果。

## 5. JSON/CSV 一致性

- CSV 用于汇总，每行对应一个可复现实验或案例。
- JSON 用于保留同一批次的完整参数、路径、逐例结果和异常详情。
- 两者必须共享 `record_id`、日期、Git 版本、结果和输出目录。
- 有官方随机场景或受控真值的，评分只可在采集完成后离线计算，并记录真值来源与隔离方式。

## 6. 提交前检查

1. 结果目录存在，且原始素材、标注/输出、`README.md` 和结构化记录相互对应。
2. 记录中没有密码、Token、账号、真值内容、内部场景文件或不可公开的大文件。
3. `README.md` 写清环境、目的、方法、结论、失败边界和复跑方式。
4. 通过离线回归后再提交；官方仿真结论必须另有真实运行证据，不能由单元测试替代。
