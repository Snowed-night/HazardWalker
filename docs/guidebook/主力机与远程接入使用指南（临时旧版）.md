# 主力机与远程接入使用指南（临时旧版）

> **状态：临时采用合并后的旧版资料。** 本文整合原“主力机环境使用、SSH 连接、远程桌面使用”三份说明，直至平台/集成组完成一次现网复验并发布正式版。地址、账号、密码、密钥、公网入口和设备标识不写入仓库，由管理员通过受控渠道提供。

## 1. 使用边界

- 日常代码开发统一在本地 `C:\hwpdepth` 完成；主力机用于 Linux/ROS、官方 SimEnv、长时运行和集成验证。
- 一人一账号、一人一工作目录；不得共享账号、密码、私钥、Token 或管理员会话。
- 图形调试才使用远程桌面；构建、测试、日志查看和普通开发优先 SSH。
- 不确认当前环境状态时，只做只读检查，禁止重启共享容器、删除进程或抢占 `/hw/cmd_vel`。

## 2. SSH 接入

1. 从管理员获取主机别名/地址、账号和首次认证方式；不要把这些信息复制到 README、脚本、截图或 Git 配置。
2. 首次连接后核对主机指纹，再检查 `pwd`、`git status -sb`、ROS 环境和可用磁盘；发现与团队公告不一致时停止操作并反馈。
3. 使用个人 SSH 密钥；公钥经管理员登记后再启用免密登录。私钥只保存在个人设备，不上传仓库或网盘。
4. 长时构建、仿真和记录任务使用 `tmux` 或等价会话工具；退出前保存日志和结果目录。
5. 仅在管理员明确允许时建立 SSH 隧道；隧道仅用于自己的会话，用完即关闭。

## 3. 远程桌面接入

- 远程桌面用于 RViz、Gazebo 图形界面、视频核验等必须图形化的任务；优先使用团队指定的内网/VPN 路径。
- 登录通常包含网关认证和 Linux 桌面账号两层；两层凭据均从管理员受控获取，禁止在文档记录。
- 登录后先确认当前用户、剩余磁盘、GPU/图形会话和是否已有共享仿真在运行；不得结束其他成员的任务。
- 图形会话异常、黑屏或断开时，先保存现有日志，随后由平台管理员处理，不自行重启显示服务或共享容器。

## 4. 主力机环境与资源规则

- 系统级 ROS、容器、GPU 驱动和公共依赖由管理员维护；个人项目依赖放入各自工作目录或受控虚拟环境。
- 构建产物、缓存、rosbag、视频、模型权重和原始大帧不混入 Git。共享大文件放团队约定目录，并在实验 README 中记录索引。
- 使用 GPU、Docker、官方 SimEnv、真实控制或长时仿真前，应确认独占时段、资源预算和清理责任。
- 遇到无深度、TF 缺失、传感器中断、控制发布者冲突或容器状态异常时，停止结论性实验并保留诊断日志。

## 5. 使用后检查

1. 终止自己启动的业务节点、tmux 会话、隧道和临时进程；不得停止非本人会话。
2. 确认没有把密码、地址、Token、rosbag、视频、缓存或模型大文件加入 Git。
3. 将测试表、日志索引和成果按 [测试记录规范](测试记录规范.md) 写入 `reports/`。
4. 发现本手册与实际环境不一致时，在 [待确认与待裁决清单](待确认/待确认与待裁决清单.md) 记录差异，并由管理员更新正式版。
