# HazardWalker 技术选型与总体方向

本文档只说明技术选型和总体系统方向。开发计划和近期任务见 [项目初期开发](../development/项目初期开发.md)。

更新时间：2026-06-07

## 1. 项目定位

HazardWalker 面向 DG-202602 “基于四足机器人的危险源自主搜索与识别技术”赛题。

核心任务：

```text
未知多层楼栋仿真环境
四足机器人自主探索建图
识别红色球体危险源
输出相对起点的三维坐标
自主返回起点
```

## 2. 主技术选型

| 方向 | 当前选型 | 作用 |
|---|---|---|
| 操作系统 | Ubuntu 24.04 | 主力机和 ROS 2 Jazzy 推荐环境 |
| 通信框架 | ROS 2 Jazzy | 节点通信、话题、launch、参数管理 |
| 主仿真 | Gazebo Harmonic | 自建楼栋场景、传感器和机器人仿真 |
| 官方平台 | 待官方发布/确认 | 最终比赛环境适配 |
| 导航 | Nav2 | 目标点导航、路径规划、局部避障 |
| SLAM | SLAM Toolbox | 建图和定位 |
| 探索 | Frontier 起步 | 从未知区域边界开始探索 |
| 感知 | OpenCV / HSV | 快速检测红色球体，建立基础链路 |
| 增强感知 | YOLO / 深度学习预研 | 复杂场景下提升识别鲁棒性 |
| 定位 | 相机 + 点云/深度 + TF | 将图像检测结果转换成三维坐标 |
| 决策 | FSM 状态机 | 管理探索、检测、确认、返航、失败等任务状态 |
| 结果 | JSON / CSV | 保存结果和统计指标 |

## 3. 仿真平台

Gazebo Harmonic 作为当前主线：

- 与 ROS 2 Jazzy 配套。
- 方便接 Nav2、SLAM Toolbox、RViz2、rosbag2。
- 适合做最小 demo、传感器仿真和自动化测试。
- 能在官方平台明确前，先稳定内部 `/hw/*` 接口。

官方平台发布后，平台层需要通过 adapter 转换到内部接口，尽量避免算法节点大改。

## 4. 感知与定位

赛题危险源被抽象为红色球体，因此第一阶段用 HSV 检测作为确定性基线：

- 不需要训练数据。
- 不需要 GPU 推理。
- 普通成员可以用离线测试参与。
- 方便先打通感知、决策和结果输出链路。

正式定位链路应是：

```text
2D bbox
  -> CameraInfo / 深度 / 点云
  -> TF 坐标变换
  -> 相对起点 xyz
  -> 多帧确认
  -> 空间去重
  -> 结果输出
```

YOLO 或其他深度学习方法作为增强方向，用于处理光照变化、遮挡和干扰物。

## 5. 导航与探索

完整未知环境自主探索需要 SLAM、地图、导航、失败恢复和探索终止判断。

基础导航方向：

```text
SLAM Toolbox 建图
Nav2 goal 接入
Frontier 探索目标生成
卡死判定
返航触发
起点回归验证
```

## 6. 决策与评估

决策层采用 FSM 管理任务阶段：

```text
初始化
探索
目标检测
目标确认 / 重观察
返航
完成 / 失败
```

评估结果以 JSON / CSV 记录，核心指标包括探索耗时、识别率、虚警率、定位误差、返航成功率和失败原因。
