# HazardWalker 项目背景介绍

## 1. 项目基本信息

- 项目名称：HazardWalker
- 赛题编号：DG-202602
- 赛题名称：基于四足机器人的危险源自主搜索与识别技术
- 项目目标：在未知多层楼栋仿真环境中，让四足机器人自主探索、识别红色球体危险源、完成三维定位、输出结果并自主返航。

## 2. 任务定义

- 机器人从固定起点出发，坐标原点以任务起点为准。
- 主要识别目标是红色球体危险源。
- 系统需要输出危险源相对起点的三维坐标和任务结果。
- 项目当前以仿真环境和离线算法为主，先固定接口和最小闭环，同时并行推进正式比赛需要的自主探索、三维定位、任务决策和指标统计。

## 3. 系统结构

```text
仿真平台 / 官方平台
        |
hazardwalker_platform
        |
HazardWalker 内部接口
        |
nav / perception / decision
        |
hazardwalker_bringup
        |
结果输出 / 指标统计
```

### 3.1 模块职责

- `hazardwalker_platform`：平台适配，统一仿真和官方平台输入输出，负责 Gazebo 和官方平台到 `/hw/*` 的转换。
- `hazardwalker_nav`：固定航点、Frontier/SLAM/Nav2、自主探索、返航和卡死恢复。
- `hazardwalker_perception`：红球检测、相机雷达融合、三维定位、多帧确认和去重。
- `hazardwalker_decision`：任务状态机、探索决策、重观察、返航约束和结果汇总。
- `hazardwalker_bringup`：一键启动和系统集成。
- `hazardwalker_msgs`：自定义消息定义。

## 4. 核心接口

### 4.1 传感器与控制

- `/hw/camera/image_raw`：相机原始图像，感知模块用它检测红色球体。
- `/hw/camera/camera_info`：相机内参，三维定位和点云投影需要使用。
- `/hw/lidar/points`：激光雷达点云，用于估计危险源三维位置。
- `/hw/odom`：机器人里程计，导航和决策模块用它判断当前位置和运动状态。
- `/hw/cmd_vel`：机器人速度控制指令，导航模块输出，平台适配层接收。
- `/tf`：动态坐标变换，例如 `odom -> base_link`。
- `/tf_static`：静态坐标变换，例如传感器相对机器人底盘的位置。

### 4.2 导航与任务

- `/hw/nav/state`：导航状态，例如 `NAVIGATING`、`RETURNING`、`FINISHED`。
- `/hw/nav/goal`：内部导航目标，决策模块可通过它给导航模块下发 Frontier、重观察或返航目标点。
- `/hw/perception/hazard_detections`：危险源检测结果，当前最小 demo 用 JSON 字符串表示。
- `/hw/mission/state`：任务状态，给其他模块和测试脚本观察任务进度。
- `/hw/mission/result`：任务最终结果，当前用于发布 result JSON。

## 5. 已确认工程原则

- `hazardwalker_platform` 是唯一平台适配入口。
- 算法模块只面向 `/hw/*` 内部接口。
- 第一阶段用固定航点和 HSV 跑通最小闭环，同时各组并行推进 Gazebo/官方平台适配、Frontier/SLAM/Nav2、点云三维定位、完整 FSM 和指标统计。
- YOLO/NBV、主动重观察等增强模块先做小实验和技术储备，再按识别率、虚警率、定位精度和探索效率收益接入主流程。
- 官方平台发布后优先做平台适配，不直接重写算法。
- 主力机用于集成，个人环境用于模块开发。
