## 2. 当前最小 demo

当前最小 demo 用于验证平台、导航、感知、决策和结果输出能串起来。

```text
fake_platform_node
    -> 发布 /hw/camera/image_raw、/hw/camera/camera_info、/hw/odom、/tf、/hw/lidar/points
    -> 接收 /hw/cmd_vel

hsv_detector_node
    -> 订阅 /hw/camera/image_raw
    -> 发布 /hw/perception/hazard_detections

waypoint_patrol_node
    -> 订阅 /hw/odom
    -> 发布 /hw/cmd_vel 和 /hw/nav/state

mission_state_machine_node
    -> 订阅 /hw/nav/state 和 /hw/perception/hazard_detections
    -> 发布 /hw/mission/state
    -> 写出 reports/run_results/<timestamp>_result.json
```

当前最小 demo 的边界：

- 平台：仍以 `fake_platform_node` 为主。
- 感知：当前 HSV 检测主要输出 2D bbox。
- 导航：当前是固定航点验证接口。
- 决策：当前是最小状态收集和结果写出。
- 结果：危险源状态仍需要多帧确认和空间去重。

## 3. Gazebo Phase 1 进展

平台组远程分支 `origin/feature/platform` 已新增 Gazebo 最小仿真初期功能。

当前新增内容：

```text
ros2_ws/src/hazardwalker_platform/worlds/hazardwalker_minimal.sdf
ros2_ws/src/hazardwalker_platform/models/simple_robot/model.sdf
ros2_ws/src/hazardwalker_platform/models/red_ball/model.sdf
ros2_ws/src/hazardwalker_platform/config/ros_gz_bridge.yaml
ros2_ws/src/hazardwalker_platform/launch/gazebo_minimal.launch.py
tests/offline/test_platform_phase1.py
```

当前 Gazebo 最小场景能力：

- 10m x 10m x 3m 单房间场景。
- 原点作为机器人起点。
- 红球位于 `(2.0, 0.0, 0.6)`。
- `simple_robot` 带相机、LiDAR、IMU 和 DiffDrive。
- `ros_gz_bridge` 将 Gazebo 话题桥接到 `/hw/camera/image_raw`、`/hw/lidar/points`、`/hw/lidar/scan`、`/hw/odom`、`/tf`、`/cmd_vel` 等接口。
- 离线测试可在不依赖 ROS/Gazebo 的情况下校验 SDF、模型、桥接配置和启动文件完整性。

## 4. 当前怎么测试

普通 Python 环境下先运行：

```bash
python3 scripts/run_offline_tests.py
```

有 Ubuntu 24.04 + ROS 2 Jazzy 环境后，再运行：

```bash
./scripts/build.sh
./scripts/run_minimal_demo.sh
python3 scripts/evaluate_result.py reports/run_results/<timestamp>_result.json
```

平台组在主力机上还应验证：

```bash
ros2 launch hazardwalker_platform gazebo_minimal.launch.py
ros2 launch hazardwalker_platform gazebo_minimal.launch.py headless:=true
```

## 5. 下一阶段重点

近期共同目标：

1. 全员 clone 仓库，能说明自己负责模块的输入、输出和近期任务。
2. 各组在主力机对应账号下跑通离线测试。
3. 集成组保持 `dev` 分支可构建、可运行、可评估。
4. 平台组验证 Gazebo 最小场景，推进 Gazebo adapter 和楼栋最小场景需求。
5. 导航组从固定航点推进到 Frontier、SLAM Toolbox、Nav2 和返航策略。
6. 感知组从 HSV 2D bbox 推进到相机 + 点云/深度 + TF 的三维定位。
7. 决策组把最小状态收集升级为探索、识别、重观察、返航、失败处理 FSM。
8. 测试组建立探索耗时、识别率、虚警率、定位误差、返航成功率的记录方式。
9. 文档组同步赛事报名、盖章、材料流程，并维护一句话项目介绍和系统框图。

## 6. 各组近期交付

- 平台组：能在主力机拉起 Gazebo 最小场景，列出楼栋场景和官方平台 adapter 的接口差异。
