# HazardWalker 项目上下文

本文档用于在新成员加入、切换对话、进行技术选型或整理参赛材料时快速恢复项目背景。

## 1. 项目基本信息

- 项目名称：HazardWalker
- 赛题编号：DG-202602
- 赛题名称：基于四足机器人的危险源自主搜索与识别技术
- 发榜单位：西南技术物理研究所
- 项目目标：在未知多层楼栋仿真环境中，使四足机器人自主探索、识别危险源、完成三维定位、输出结果并自主返航。

## 2. 赛题任务理解

官方测试任务可以概括为：

```text
四足机器人从固定起点出发，
在未知多层楼栋仿真环境中自主探索，
利用可见光相机和激光雷达识别随机生成的红色球体危险源，
输出危险源相对出发点的三维坐标，
完成探索后自主返回起点。
```

已明确的约束：

- 不允许人工遥控干预。
- 不允许修改楼房模型、机器人出发点、传感器类型和危险源随机生成过程。
- 危险源在比赛测试中抽象为红色球体。
- 坐标原点为机器人出发点。
- 需要在官方仿真平台中完成测试。
- 任务核心是自主探索、危险源识别定位和返航，不是从零开发四足步态控制。

尚需等待官方平台确认的信息：

- 机器人模型和控制接口。
- 相机、激光雷达的具体型号、话题、频率和坐标系。
- 楼栋场景规模、楼层数量和地图大小。
- 官方评测脚本和结果输出格式。
- “全覆盖探索”和“5% 定位误差”的具体判定方式。

## 3. 评分重点

项目优化应围绕官方评分指标展开：

- 探索效率：平均探索并返航时间，600 秒以内更有优势。
- 危险源识别概率：正确识别并定位的危险源比例。
- 虚警率：错误报警比例，必须控制误检。
- 系统稳定性：仿真过程中不能崩溃、卡死或需要人工干预。
- 代码规范性与可复现：依赖明确、结构清晰、一键运行。
- 工程完备性：报告、实验、分析、迁移路径和答辩表达完整。

## 4. 当前推荐技术路线

总体路线是先保证完整闭环，再逐步强化创新和指标。

系统主链路：

```text
仿真平台 / 官方平台
        |
平台适配层
        |
SLAM / 定位 / 建图
        |
自主探索与导航
        |
危险源识别与三维定位
        |
主动决策 / 重观察 / 返航约束
        |
结果输出 / 指标统计 / 自测试报告
```

推荐模块：

- `hazardwalker_platform`：平台适配，统一官方/自建仿真接口。
- `hazardwalker_nav`：SLAM、Frontier 探索、路径规划、返航、卡死恢复。
- `hazardwalker_perception`：红球检测、相机雷达融合、三维定位、多帧确认、去重和虚警抑制。
- `hazardwalker_decision`：危险源信念地图、全局 NBV、主动重观察、返航约束和任务状态机。
- `hazardwalker_bringup`：一键启动、参数加载和系统集成。
- `hazardwalker_msgs`：自定义消息、服务和动作。

## 5. 推荐算法方向

基础版本：

- ROS/Gazebo 或官方平台适配。
- SLAM / 建图 / 定位。
- Frontier-based exploration。
- OpenCV HSV 红色球体检测。
- 点云辅助三维定位。
- 多帧确认与空间聚类去重。
- 自主返航。

进阶创新版本：

- 带负观测更新的危险源信念地图。
- 面向危险源发现收益的全局 Next-Best-View。
- 视觉语义置信度与激光几何置信度融合。
- 基于定位不确定性的主动重观察。
- 搜索、确认、重观察、返航统一任务决策。
- 返航时间约束下的探索目标选择。

创新表达建议：

```text
本项目不是重新发明 NBV 或语义地图，而是面向四足机器人危险源搜索任务，
将危险源信念更新、主动搜索、可信定位、主动重观察和返航约束统一为闭环决策框架。
```

## 6. 团队分工

当前建议按 10 人左右组织，采用主岗 + 副岗方式。

- 技术总负责人：统一技术路线、系统架构、接口规范和最终集成。
- 平台与仿真组：ROS/Gazebo、自建场景、官方平台适配、传感器和控制接口。
- 导航探索组：SLAM、Frontier、NBV、路径规划、返航和卡死恢复。
- 感知定位组：红球检测、相机雷达融合、三维定位、多帧确认、去重和虚警抑制。
- 系统集成与测试组：一键启动、参数管理、自动测试、指标统计和完整流程跑测。
- 文档答辩与监督组：报名、会议跟进、技术报告、自测试报告、PPT、演示视频、专利论文材料。

## 7. 工程实施原则

环境建议：

```text
1 台主力集成机 + 每个人本地开发环境 + 统一 Docker/脚本
```

主力集成机负责：

- 完整仿真运行。
- 官方平台联调。
- 录制演示视频。
- 运行最终测试。

个人环境负责：

- 各自模块开发。
- 小样例测试。
- 文档和脚本修改。

工程规则：

- 所有成果进入 Git 仓库。
- 所有接口变更同步更新 `docs/interface_spec.md`。
- 大文件、rosbag、视频、模型权重不直接提交 Git。
- 每两周至少做一次系统联调。
- 指标必须数据化记录，包括探索时间、识别率、虚警率、定位误差、返航成功率和崩溃次数。

## 10. 下一步技术选型参考

技术选型参考：

1. 官方平台未公布前，自建仿真平台采用 ROS 2 + Gazebo 还是 ROS 1 + Gazebo Classic。
2. 导航框架采用 Nav2、move_base，还是自定义轻量导航。
3. SLAM 采用 SLAM Toolbox、Cartographer、FAST-LIO2、LIO-SAM 或其他方案。
4. 红球检测先用 OpenCV HSV，是否需要训练 YOLO 辅助。
5. 相机雷达融合如何做坐标标定、点云投影和目标中心估计。
6. 自主探索采用基础 Frontier，还是加入 NBV 和危险源信念地图。
7. 返航和卡死恢复如何工程化实现。
8. 如何设计自动化测试和指标统计脚本。
