# HazardWalker 主力机远程桌面使用指南

更新时间：2026-06-07

适用对象：全队成员

目标机器：`hxbl`（Ubuntu 24.04 + GNOME Remote Login）

> 本仓库版本不保存明文密码。RDP 网关密码和各组临时 Linux 密码只通过队内私有渠道发送。

## 1. 适用场景

远程桌面用于 RViz、Gazebo GUI 等图形界面开发。无 GUI 需求时仍优先 SSH。

多组可以同时连接，各用各的 Linux 账号，桌面环境隔离。

## 2. 两层登录

连接远程桌面时会先后出现两次登录：

1. RDP 网关登录：使用队内统一 RDP 网关账号。
2. GDM Linux 登录：使用本组 `hazard_*` Linux 账号。

不要把两层账号密码混用。明文凭据见队内私有版本，不写入仓库。

## 3. 连接地址

| 路径 | 何时使用 | RDP 地址 |
|---|---|---|
| Tailscale | 本机已安装并登录 Tailscale | `100.102.91.31:3389` |
| 公网跳板 | 无 Tailscale | 先开 SSH 隧道，再 RDP 连接 `127.0.0.1:13389` |

证书为自签，客户端提示时选择继续、是或信任。

## 4. Windows 连接步骤

### 4.1 Tailscale 路径

1. 安装 Tailscale for Windows 并登录。
2. `Win + R` 输入 `mstsc`。
3. 计算机填写 `100.102.91.31:3389`。
4. 第一层使用 RDP 网关账号。
5. GDM 界面使用本组 Linux 账号。

### 4.2 公网跳板路径

在本机 PowerShell 或 CMD 中执行，账号替换为本组账号：

```powershell
ssh -p 6002 hazard_按本组修改@47.98.141.33 -L 13389:127.0.0.1:3389
```

保持该窗口不关闭，然后打开 `mstsc`，连接：

```text
127.0.0.1:13389
```

## 5. macOS 连接步骤

推荐客户端：Microsoft Remote Desktop / Windows App。

Tailscale 路径直接新建 RDP 连接：

```text
100.102.91.31:3389
```

公网跳板路径先在本机终端执行：

```bash
ssh -p 6002 hazard_按本组修改@47.98.141.33 -L 13389:127.0.0.1:3389
```

再用 RDP 客户端连接：

```text
127.0.0.1:13389
```

如果 macOS 客户端出现 `0x207`，可导出 `.rdp` 文件，将：

```text
use redirection server name:i:0
```

改为：

```text
use redirection server name:i:1
```

再双击修改后的 `.rdp` 文件连接。

## 6. SSH 配置模板

写入本机 SSH 配置文件，账号按本组替换：

```sshconfig
Host hxbl-rdp-tunnel
    HostName 47.98.141.33
    Port 6002
    User hazard_按本组修改
    LocalForward 13389 127.0.0.1:3389

Host hxbl-ts
    HostName 100.102.91.31
    User hazard_按本组修改
```

用法：

```bash
ssh hxbl-rdp-tunnel
```

保持隧道窗口不关闭，再用 RDP 连接 `127.0.0.1:13389`。

### 6.1 负责人多账号别名

负责人本机可以为每组配置独立 SSH 别名，便于查看各组进度。示例别名如下：

| 用途 | SSH 别名 | RDP 本地地址 |
|---|---|---|
| 集成组 | `hxbl-integration` / `hxbl-integration-ts` | `127.0.0.1:13391` |
| 平台组 | `hxbl-platform` / `hxbl-platform-ts` | `127.0.0.1:13392` |
| 导航组 | `hxbl-nav` / `hxbl-nav-ts` | `127.0.0.1:13393` |
| 感知组 | `hxbl-perception` / `hxbl-perception-ts` | `127.0.0.1:13394` |
| 决策组 | `hxbl-decision` / `hxbl-decision-ts` | `127.0.0.1:13395` |
| 测试组 | `hxbl-test` / `hxbl-test-ts` | `127.0.0.1:13396` |
| 文档组 | `hxbl-docs` / `hxbl-docs-ts` | `127.0.0.1:13397` |

公网 RDP 隧道对应：

```bash
ssh hxbl-rdp-integration
ssh hxbl-rdp-platform
ssh hxbl-rdp-nav
ssh hxbl-rdp-perception
ssh hxbl-rdp-decision
ssh hxbl-rdp-test
ssh hxbl-rdp-docs
```

每个隧道使用不同本地端口，可以同时打开多个 SSH 隧道窗口。RDP 第二层 GDM 登录时仍使用要查看的对应 Linux 账号。

负责人本机已把 RDP 第一层网关凭据保存到 Windows 凭据管理器。SSH 和 GDM 的 Linux 账号密码不能写进 OpenSSH 配置自动登录；需要手动输入，或后续改为 SSH 公钥。

## 7. 登录后快速检查

在远程桌面终端中：

```bash
whoami
echo $ROS_DOMAIN_ID
ros2 --help | head -1
```

文档组 `ROS_DOMAIN_ID` 为空，其余组见 [主力机环境使用指南](主力机环境使用指南.md)。

## 8. 必须遵守

- 用本组 Linux 账号登录 GDM，不共用他人账号。
- GPU 使用先报备。
- 长时间任务请用 SSH + `tmux`，不要依赖 RDP 会话。
- 公网 RDP 隧道要在自己的电脑上开，不要在 hxbl 里再 `ssh -L`。
- 不要把含密码版本的指南转发到公开群聊或提交到仓库。

## 9. 常见问题

**Q：连 `127.0.0.1:13389` 失败？**

A：确认 SSH 隧道在你自己的电脑上运行且未关闭。

**Q：第一层密码不对？**

A：第一层必须使用 RDP 网关账号，不是 Linux 账号。

**Q：GDM 密码不对？**

A：GDM 使用本组 `hazard_*` Linux 账号和对应临时密码。

**Q：禁用 SSH 密码登录后，远程桌面密码会变吗？**

A：不会。禁用 SSH 密码登录只影响 `ssh` 连入方式。公网 RDP 隧道会改用 SSH 公钥建立，但 RDP 网关和 GDM 登录机制不变。
