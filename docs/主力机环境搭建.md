# 主力机环境搭建

本文档用于说明 HazardWalker 主力机 `hxbl` 的当前环境、团队统一环境和各账号独立开发环境。

核心原则：

- 系统级依赖由环境负责人统一安装和维护。
- 各组账号默认不使用 `sudo`，只在自己的 home 目录开发。
- Docker 权限单独申请，不默认开放。
- GPU 使用需要报备，集成测试账号优先。
- 大文件可以走共享只读目录，代码仓库、构建产物和 Python 虚拟环境不要跨用户共享。

## 6. 不建议共享的内容

不要跨用户共享或软链这些目录：

```text
各组 HazardWalker 仓库
ros2_ws/build/
ros2_ws/install/
ros2_ws/log/
各组 Python venv
各组临时实验输出
```

原因：

```text
1. colcon 的 build/install/log 和当前源码、环境变量、包路径强相关，共享后容易互相污染。
2. Python 虚拟环境包含绝对路径和用户权限信息，跨用户软链后容易出权限和版本问题。
3. 各组独立仓库更方便定位问题、做分支切换和回滚。
```

## 7. 大文件共享目录

大型数据、模型、rosbag、视频可以走共享只读目录，避免重复占用空间。

当前 `/data` 已满，不再写入新文件。`/srv/hazardwalker` 已挂载在机械硬盘上，作为当前共享大文件目录，适合放归档、rosbag、视频、模型或低频访问资料。

建议由管理员创建：

```bash
sudo mkdir -p /srv/hazardwalker/datasets
sudo mkdir -p /srv/hazardwalker/models
sudo mkdir -p /srv/hazardwalker/rosbags
sudo mkdir -p /srv/hazardwalker/videos
sudo groupadd hazardwalker || true
sudo chgrp -R hazardwalker /srv/hazardwalker
sudo chmod -R 2755 /srv/hazardwalker
```

各组如需访问共享数据，可加入 `hazardwalker` 组：

```bash
sudo usermod -aG hazardwalker <username>
```

各账号可以在自己的 home 下建立软链：

```bash
ln -s /srv/hazardwalker/datasets ~/datasets
ln -s /srv/hazardwalker/models ~/models
ln -s /srv/hazardwalker/rosbags ~/rosbags
ln -s /srv/hazardwalker/videos ~/videos
```

原则：

```text
系统依赖统一安装。
大文件共享只读目录。
代码仓库、构建结果、Python 虚拟环境不跨用户共享。
```

## 8. Docker 权限

普通账号默认不给 Docker 权限。Docker 权限单独申请，由环境负责人批准。

当前 Docker 已安装并启用：

```text
Docker version：29.1.3
docker.service：enabled / active
当前 docker 组成员：hxbl, hazard_admin
```

如果需要 Docker，管理员统一安装：

```bash
sudo apt install -y docker.io
sudo systemctl enable --now docker
```

批准某账号使用 Docker：

```bash
sudo usermod -aG docker <username>
```

用户重新登录后权限生效。

注意：

```text
加入 docker 组基本等价于拥有较高系统权限，因为用户可以通过容器挂载宿主机目录。
禁用 sudo 后，不应默认给所有人 Docker 权限。
```

建议规则：

```text
1. 普通组员默认无 Docker 权限。
2. 平台组确实需要 Docker 时，单独申请。
3. GPU Docker 和 NVIDIA Container Toolkit 由环境负责人统一配置。
4. 能用系统 ROS/Gazebo 直接跑的任务，不优先使用 Docker。
```

NVIDIA Container Toolkit 是否安装，取决于后续是否要跑 GPU Docker。这个属于系统级大环境改动，不能由组员各自安装。

## 10. SSH 登录策略

最终建议禁用普通密码登录，只允许 SSH key 登录。

当前 SSH 服务状态：

```text
ssh.service：enabled / active
reverse-ssh.service：enabled / active
tailscaled.service：enabled / active
```

当前 sshd 有效配置摘要：

```text
Port 22
PermitRootLogin without-password
PubkeyAuthentication yes
PasswordAuthentication yes
KbdInteractiveAuthentication no
AuthorizedKeysFile .ssh/authorized_keys .ssh/authorized_keys2
```

这说明当前仍处于允许密码登录阶段。等所有成员 SSH key 配置并验证后，再关闭密码登录。

实施顺序：

```text
第一阶段：建号和发 key 阶段，临时允许密码登录。
第二阶段：确认每个成员都能用 SSH key 登录后，关闭密码登录。
```

每个用户把自己的公钥放到：

```text
/home/<username>/.ssh/authorized_keys
```

权限要求：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

确认所有用户 key 登录正常后，由管理员修改：

```bash
sudo vim /etc/ssh/sshd_config
```

建议配置：

```text
PubkeyAuthentication yes
PasswordAuthentication no
PermitRootLogin no
KbdInteractiveAuthentication no
```

重载 SSH：

```bash
sudo systemctl reload ssh
```

重载前必须保留一个已经登录的管理员终端，不要直接断开当前 SSH，避免配置错误后锁在机器外。

如果后续要更严格，可以只允许指定用户组 SSH 登录：

```bash
sudo groupadd hazardssh || true
sudo usermod -aG hazardssh hazard_admin
sudo usermod -aG hazardssh hazard_integration
sudo usermod -aG hazardssh hazard_platform
sudo usermod -aG hazardssh hazard_nav
sudo usermod -aG hazardssh hazard_perception
sudo usermod -aG hazardssh hazard_decision
sudo usermod -aG hazardssh hazard_test
sudo usermod -aG hazardssh hazard_docs
```

然后在 `/etc/ssh/sshd_config` 中加入：

```text
AllowGroups hazardssh
```

当前建议先做到：

```text
禁止 root 登录。
确认 key 可用后禁用密码登录。
暂时不强制 AllowGroups，等账号稳定后再加。
```
