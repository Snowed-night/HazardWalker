## 6. 常见运维操作

### 6.1 为新成员添加 SSH 公钥

```bash
# 以 hazard_platform 为例
sudo mkdir -p /home/hazard_platform/.ssh
echo "<成员公钥一行>" | sudo tee -a /home/hazard_platform/.ssh/authorized_keys
sudo chmod 700 /home/hazard_platform/.ssh
sudo chmod 600 /home/hazard_platform/.ssh/authorized_keys
sudo chown -R hazard_platform:hazard_platform /home/hazard_platform/.ssh
```

**不要**把 `hxbl` 的公钥复制给其他账号；每人用自己的 key。

### 6.2 修改临时密码

```bash
echo 'hazard_platform:新密码' | sudo chpasswd
```

### 6.3 批准 Docker 权限

```bash
sudo usermod -aG docker <username>
# 提醒：docker 组等价高权限，需记录批准原因
```

### 6.4 同步文档到各账号仓库

```bash
sudo cp 主力机环境搭建总结报告.md /home/hazard_test/HazardWalker/docs/
sudo chown hazard_test:hazard_test /home/hazard_test/HazardWalker/docs/主力机环境搭建总结报告.md
```

### 6.5 检查 GPU 占用

```bash
nvidia-smi
# 长期占用未报备：联系对应组员释放
```

### 6.6 检查磁盘

```bash
df -h / /srv/hazardwalker
du -sh /srv/hazardwalker/*
```

## 8. SFTP 下载监控（可行性评估，未实施）

全队曾咨询是否能监控各账号 SFTP 下载并记日志、仅管理员可查看。

**结论：可行，推荐组合方案，尚未部署。**

| 层级 | 方案 | 日志内容 | 实施难度 |
|---|---|---|---|
| 基础 | OpenSSH `sftp-server -l INFO` | 连接、部分传输活动 | 低 |
| 推荐 | **auditd** 审计 `/home` 读操作 | 哪个用户读了哪个文件 | 中 |
| 增强 | 自定义 sftp wrapper + 独立日志文件 | 会话级详细记录 | 中高 |

推荐落地步骤（集成组执行）：

```bash
# 1. 安装 auditd
sudo apt install -y auditd
# 规则示例：监控 home 目录读取
-w /home -p r -k hazard_home_read

# 2. 增强 SFTP 日志（/etc/ssh/sshd_config.d/hazard-sftp.conf）
Subsystem sftp /usr/lib/openssh/sftp-server -f AUTHPRIV -l INFO

# 3. 日志目录仅管理员可读
sudo mkdir -p /var/log/hazardwalker-audit
sudo chown root:hazard_audit /var/log/hazardwalker-audit
sudo chmod 750 /var/log/hazardwalker-audit
sudo usermod -aG hazard_audit hxbl
sudo usermod -aG hazard_audit hazard_admin
```

查询示例：

```bash
sudo ausearch -k hazard_home_read -i
sudo grep sftp /var/log/auth.log
```

**注意：** 细粒度审计会增加磁盘 I/O 与日志量；建议先对 `hazard_*` 账号启用，试运行一周再评估。

## 9. 安全策略备忘

### 禁用密码登录（全员公钥就绪后）

```bash
# /etc/ssh/sshd_config
PasswordAuthentication no
PubkeyAuthentication yes
```

重载前**保留一个已登录的管理员终端**：

```bash
sudo systemctl reload ssh
```

### sudo 与禁用密码登录的关系

- 禁用密码登录只影响 **SSH 连入方式**（必须公钥）
- 登录后 `sudo` 仍用该账号的 **Linux 密码**（`hazard_admin` 账户密码）
- 两者独立，不冲突
