> 制定方：系统集成与测试组
> 适用范围：全组（平台、感知、导航、决策、集成测试）
> 生效日期：2026-07-03

***

## 一、为什么要填表

本阶段（6月14日-7月4日）全队要求：

```text
环境能用
命令能跑
结果能保存
截图或日志能展示
问题能记录
```

***

## 二、什么时候填

**每次运行测试后都要填**，不管成功还是失败。具体包括：

| 场景          | 说明                                    |
| ----------- | ------------------------------------- |
| 离线测试跑通      | `python scripts/run_offline_tests.py` |
| Gazebo 仿真运行 | headless 或 GUI 都算                     |
| 截图脚本执行      | `capture_red_ball_gallery.py` 等       |
| 最小 demo 运行  | `run_minimal_demo.sh`                 |
| 失败/报错复现     | 写清楚失败信息                               |

***

## 四、怎么填

### 4.1 填写步骤

1. **跑完命令后立即填**
2. **先填基本信息** — 10 个字段一个都不能少
3. **再填本组专项指标** — 有数据填数据，没数据填"未测试"或具体原因
4. **把错误信息关键部分贴进去**
5. **保存成 JSON + CSV 两种格式**

### 4.2 文件命名规则

```text
testing_record_<组名>.json
testing_record_<组名>.csv
```

组名用小写英文：`perception` / `nav` / `decision` / `platform` / `integration_test`

### 4.3 存放目录

统一放在本组的 `test_records` 目录下，用时间戳分子目录：

```text
reports/<组名>/test_records/<YYYYMMDD_HHMMSS>/
    ├─ testing_record_<组名>.json
    └─ testing_record_<组名>.csv
```

示例：

```text
reports/perception/test_records/20260621_150028/
    ├─ testing_record_perception.json
    └─ testing_record_perception.csv
```

> 注意：时间戳是测试执行的时间，不是填表时间。
