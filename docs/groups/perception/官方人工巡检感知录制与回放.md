# 官方人工巡检感知录制与回放

本文用于固定 SEED 官方复杂楼宇的人工巡检、实时红球检测、人工确认复查、数据录制和离线回放。正式运行不得读取 Gazebo 真值、场景内部文件或硬编码目标位置。

人工巡检 rosbag 用于可重复比较检测、复查和定位算法，不代表未知楼宇自主探索或整场任务已经完成。正式得分证据仍须由导航自主运行至任务结束，并同时满足任务完成状态、合法定位来源和官方随机场景证据约束。

## 1. 一次性构建

在远程 Ubuntu 主机执行：

```bash
bash
cd ~/桌面/HazardWalker/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select \
  hazardwalker_platform hazardwalker_perception hazardwalker_nav hazardwalker_bringup
```

代码变化后重新构建；同一版本重复实验不需要再次构建。

## 2. 实时人工巡检

以下命令必须在平台容器健康、控制器已站立且取得独占控制时段后执行。每个代码块使用独立终端。

### 2.1 ROS1↔ROS2 适配器

由平台管理员启动正式容器；`up` 会在容器健康后自动启动并去重 ROS2 适配器：

```bash
bash
cd ~/桌面/HazardWalker/ros2_ws/src/hazardwalker_platform
export ROS_DOMAIN_ID=42
export DOCKER_SIMENV_USER=hazard_platform
export OFFICIAL_SIMENV_ENABLE_CONTROL=1
export OFFICIAL_SIMENV_ENABLE_ODOM_RELAY=0
./auto_docker.sh up
./auto_docker.sh status
```

正式感知定位关闭 Gazebo 派生里程计转发。点云和 Livox IMU 保持默认关闭；RGB、深度、内参、TF、LaserScan 和 trunk IMU 保持开启。
适配器默认以 200 ms 周期桥接 RGB-D（上限 5 Hz）；正式巡检不得把
`OFFICIAL_SIMENV_IMAGE_THROTTLE_RATE_MS` 调到 250 ms 以上。第一人称视频仍直接读取 ROS1 压缩流，不受该原始 RGB-D 节流限制。
普通成员不得另开终端运行适配器脚本；业务节点只复用平台受管实例。

### 2.2 感知、定位和控制仲裁

```bash
bash
cd ~/桌面/HazardWalker/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=42
ros2 launch hazardwalker_bringup official_simenv_control_interface.launch.py \
  control_mode:=keyboard \
  perception_parameter_file:=$HOME/桌面/HazardWalker/config/perception.yaml \
  start_navigation:=false \
  start_slam:=true \
  slam_backend:=cartographer \
  start_decision:=false \
  localization_provenance:=lidar_imu_slam
```

该入口统一控制话题：键盘、导航和辅助对准分别写入独立输入，只有 `command_mux_node` 发布 `/hw/cmd_vel`。
感知节点同时发布完整检测载荷和独立复查建议；证据记录器不是建议话题的发布者，未启动记录器也不会中断 GUI、辅助控制或后续导航接口。

### 2.3 键盘控制

```bash
bash
cd ~/桌面/HazardWalker/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=42
ros2 run hazardwalker_platform keyboard_control_node
```

按键：`W` 前进、`S` 后退、`A` 左转、`D` 右转、`K` 立即停止。终端必须保持焦点。

### 2.4 录包前只读预检

解除 Gazebo 暂停并启动键盘节点后执行：

```bash
cd ~/桌面/HazardWalker
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=42
python3 scripts/verify_perception_live_chain.py \
  --control-source keyboard \
  --localization-provenance lidar_imu_slam \
  --sample-sec 3 \
  --output reports/perception/official_random/20260803_seed_20260803_run01/live_chain_preflight.json
```

脚本不会发布速度命令。只有输出 `"passed": true` 才开始正式巡检；失败项会明确指出无实时 `/clock`、RGB-D、激光或地图，定位来源声明与运行节点不一致，平台适配器、合法里程计或地图存在多发布者，适配器未启用控制或 GUI 转发，多节点争用 `/hw/cmd_vel`，检测/复查或巡检覆盖心跳无输出、辅助服务或覆盖清零服务缺失，以及 `http://127.0.0.1:6082/healthz` 无实时相机帧或叠加状态。正式预检还要求 RGB、深度、检测和复查建议的 3 秒实测频率均不低于 2 Hz，覆盖心跳不低于 0.5 Hz，最终控制输出不低于 5 Hz，并要求当前代码和配置已经提交。第一人称门禁会核对画面与检测时间差不超过 0.25 秒，且叠加载荷完整包含画面尺寸、候选列表和复查建议。导航接管时将 `--control-source` 改为 `navigation`。`--graph-only` 仅用于排查端点，不检查第一人称页面，也不检查工作树，不能作为正式录包门禁。

### 2.5 人工确认后辅助居中

第一人称页面出现“需复查”候选后，由操作员确认周围可安全原地转向，点击页面“辅助对准”并在确认框中确认。页面只发送 `start/cancel` 请求；ROS2 适配器调用既有辅助服务，实际角速度仍由辅助节点经 `command_mux_node` 输出，网页不能直接发布速度。辅助会话锁定点击时的目标；推荐目标变化不会换球，原目标消失则立即停止。

页面不可用时，可在 ROS2 终端执行同一启动服务：

```bash
ros2 service call /hw/control/assist_align/start std_srvs/srv/Trigger '{}'
```

取消复查可点击“取消辅助”，或执行：

```bash
ros2 service call /hw/control/assist_align/cancel std_srvs/srv/Trigger '{}'
```

辅助节点只执行限时原地转向。启动后必须先从 `/hw/control/status` 收到 `mode=assist` 的接管确认，接管期间会短时重试模式请求但不会提前发送非零速度；1.5 秒仍未接管则失败停车。重复点击启动不会重置正在执行的会话。目标消失、感知超时或达到时限时同样立即停车，并把控制权归还给接管前的键盘或导航模式。

### 2.6 控制模式切换

```bash
ros2 topic pub --once /hw/control/mode_request std_msgs/msg/String "{data: 'keyboard'}"
ros2 topic pub --once /hw/control/mode_request std_msgs/msg/String "{data: 'navigation'}"
ros2 topic pub --once /hw/control/mode_request std_msgs/msg/String "{data: 'stopped'}"
```

只有启动参数包含 `start_navigation:=true` 时才能切换到 `navigation`。切换瞬间和控制源超时后均输出零速度。

## 3. 固定 SEED 数据录制

原始 rosbag 体积较大，保存在主机数据盘，不提交 Git。最终回放结果、代表图、指标和测试记录保存到 `reports/perception/`。

```bash
bash
cd ~/桌面/HazardWalker
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=42
python3 scripts/official_perception_bag.py record \
  --output /data/hazardwalker_bags/seed_20260803_run01 \
  --seed 20260803 \
  --run-id seed_20260803_run01 \
  --operator 姜晨 \
  --localization-provenance lidar_imu_slam \
  --preflight-report reports/perception/official_random/20260803_seed_20260803_run01/live_chain_preflight.json
```

脚本在启动 rosbag 前调用覆盖清零服务，因此预检阶段或上一轮的移动不会计入本轮。巡检完成后按 `Ctrl+C`。脚本记录 RGB、深度、双相机内参、LaserScan、trunk IMU、TF、合法定位及其运行时来源声明、地图、巡检覆盖心跳、受管适配器状态、三类控制输入、最终控制输出、检测、复查建议和任务状态，并写出 `run_manifest.json`。正式录制必须显式声明固定 SEED、白名单内的 SLAM 定位来源，并提供五分钟内生成且通过的实时预检报告；报告与录包必须来自同一个干净 Git 提交，报告哈希、控制源和定位来源随清单保存。录制进程退出后，脚本直接统计 rosbag SQLite 数据库中的逐话题消息数和首尾时间戳，并读取最终覆盖状态；任一关键话题为零、数据库损坏、完整时间跨度不足 60 秒、合法位姿样本少于 20、平面路程不足 8 m 或平面覆盖跨度不足 3 m 时，清单状态写为 `invalid`，该轮不得进入算法对比。该门槛用于排除静止录包和入口短距离探测，不代表已经覆盖全部楼层。

脚本默认等待关键话题 20 秒。RGB、深度、双相机内参、LaserScan、trunk IMU、TF、合法 SLAM 里程计、`/map`、控制仲裁及辅助状态、最终控制、检测或复查建议缺失时拒绝开始录制；键盘输入和导航输入至少有一个存在即可，因此切换为自主探索无需修改录包链路。正式巡检不得使用 `--skip-topic-preflight` 或 `--allow-dirty-worktree`；这两个参数同时出现时仅生成不进入回归集的诊断录包。

rosbag 使用官方 `/clock` 作为记录时间轴；回放由 rosbag 播放器生成唯一 `/clock`，不重复发布袋内历史时钟，使图像、深度、TF 和算法仿真时间保持一致。历史适配器状态只回放到 `/hw/replay/*` 审计命名空间，不会伪装成当前在线平台状态。`run_manifest.json` 同时保存预检话题列表、固定 SEED、代码版本、定位来源、原始录制命令、逐话题消息计数、录制时间跨度及所有 bag 文件的内容指纹。回放器与回归集索引器会重新读取 SQLite 并重算内容指纹，不会仅信任清单里的 `passed` 文本。只有声明白名单内合法 SLAM、且里程计与 TF 均实际录到消息时，历史定位才允许在回放中复用；否则必须追加 `--recompute-localization`。

至少三个随机 SEED 完成有效巡检后建立正式回归集索引。每个 `--session` 对应一个不同 SEED；脚本默认执行 `--min-seeds 3`，并拒绝无效数据和重复 SEED，避免从同一场景的多次巡检中事后挑选最好结果。

```bash
python3 scripts/build_perception_bag_regression_catalog.py \
  --session /data/hazardwalker_bags/seed_20260803_run01 \
  --session /data/hazardwalker_bags/seed_20260804_run01 \
  --session /data/hazardwalker_bags/seed_20260805_run01 \
  --output-dir /data/hazardwalker_bags/perception_regression_v1
```

索引目录生成 `regression_catalog.json` 和 `regression_catalog.csv`，记录每个 SEED 的唯一基准巡检、Git 版本、数据量、时长、实际路程和覆盖跨度，以及 RGB-D、雷达、IMU、SLAM、地图、检测和控制消息数。

## 4. 离线回放

回放使用独立 `ROS_DOMAIN_ID`，不得与在线机器人共域。

### 4.1 推荐：单命令受控回放

完成一次有效录包后，优先使用以下入口。它会检查数据集状态，在独立 ROS 域启动实际参数、播放 rosbag、安全停止业务 launch，并验证结果目录；目录已存在时拒绝覆盖。正式回放前必须提交本轮代码和配置，未提交改动会被拒绝。正式结果必须写入仓库 `reports/perception/` 的独立子目录；只有不纳入成果的临时调试才可同时显式使用 `--allow-external-output --allow-dirty-worktree`。`reports/perception/`、ROS 构建目录以及官方 `auto.sh` 按 SEED 生成的 `hazardwalker_platform/generated_building/`、`results/` 和 `logs/` 不计为算法代码改动；场景生成器源码、启动脚本和配置仍严格计入。感知算法不得读取生成目录中的真值。门禁要求逐帧记录、原始/标注代表图、配对深度、合法 SLAM 轨迹、地图快照、README、失败说明及 CSV/JSON 测试表全部存在。代表图按检测时间戳从有界缓存匹配最近 RGB，再匹配深度；两级时间差写入 `frames.jsonl`，超过清单阈值时拒绝作为同步证据。

官方随机 SEED 巡检与回放写入 `reports/perception/official_random/`；为多球粘连、部分可见、红色物品抑制、复杂场景多视角或三维定位专门设计的仿真，写入 `reports/perception/simulation/3d_native/official_simenv_YYYYMMDD_<实验类别>/`，不得混用两类证据。

```bash
bash
cd ~/桌面/HazardWalker
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
python3 scripts/run_perception_replay_experiment.py \
  --session /data/hazardwalker_bags/seed_20260803_run01 \
  --output-dir reports/perception/official_random/20260803_seed_20260803_run01_hsv_baseline \
  --parameter-file config/perception.yaml \
  --algorithm-label hsv_depth_tf_baseline \
  --domain-id 142
```

首次没有标注时，结果状态为 `captured_unlabeled`，用于选帧和制作人工标注，不能进入算法横向比较。标注完成后使用新的输出目录重跑，并追加 `--annotations annotations/seed_20260803_run01.json`；只有检出率、误检、确认耗时、定位误差计算完成且实际参数合同通过，状态才是 `complete`。脚本会把本轮实际使用的参数固化为 `perception_config.yaml`，提供标注时同时固化为 `evaluation_annotations.json`，并记录两者哈希；快照被改动后该轮证据失效。重新计算当前定位与 SLAM 时追加 `--recompute-localization --localization-provenance lidar_imu_slam`。每组算法或参数必须使用新的输出目录。

### 4.2 手工分终端回放

以下流程用于排障或观察节点日志。复用录制时的定位与 TF、只比较感知算法时，终端一执行：

终端一：

```bash

source install/setup.bash
export ROS_DOMAIN_ID=142
ros2 launch hazardwalker_bringup official_simenv_control_interface.launch.py \
  control_mode:=stopped \
  perception_parameter_file:=$HOME/桌面/HazardWalker/config/perception.yaml \
  start_assist_alignment:=false \
  start_navigation:=false \
  start_slam:=false \
  start_legal_localization:=false \
  start_decision:=false \
  start_evidence_recorder:=true \
  evidence_output_dir:=$HOME/桌面/HazardWalker/reports/perception/official_random/20260803_seed_20260803_run01 \
  test_record_dir:=$HOME/桌面/HazardWalker/reports/perception/official_random/20260803_seed_20260803_run01 \
  scenario_seed:=20260803 \
  code_version:=$(git -C ~/桌面/HazardWalker rev-parse --short HEAD) \
  localization_provenance:=lidar_imu_slam
```

终端二：

```bash
bash
cd ~/桌面/HazardWalker
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=142
python3 scripts/official_perception_bag.py replay \
  --session /data/hazardwalker_bags/seed_20260803_run01
```

默认回放不会发布历史 `/hw/cmd_vel`、检测结果或复查结果。

回放结束后，该轮目录包含原始/标注代表图、`README.md`、`summary.json`、`testing_record_perception.csv`、对应 JSON、逐帧记录、运行清单和失败说明，不应再把本轮测试表写入会被下一轮覆盖的公共固定文件。

### 4.3 重新计算定位与 SLAM

启动回放前，将终端一改为 `start_slam:=true`、`start_legal_localization:=true`；终端二追加：

```bash
--recompute-localization
```

该模式只回放公开原始传感器，不发布历史 TF、里程计和地图，避免新旧定位链冲突。

## 5. 人工标注指标

复制 `config/perception_replay_annotations.example.json`，按 `frames.jsonl` 的 `record_index` 标注红球框。负样本帧保留空 `objects`。三维参考仅允许人工测量或赛后公开参考，且使用 `start` 坐标系。

```bash
python3 scripts/evaluate_perception_replay.py \
  --frames reports/perception/official_random/20260803_seed_20260803_run01/frames.jsonl \
  --annotations annotations/seed_20260803_run01.json \
  --output-dir reports/perception/official_random/20260803_seed_20260803_run01 \
  --scenario seed_20260803_run01 \
  --algorithm-label hsv_depth_tf_baseline \
  --parameter-file config/perception.yaml
```

输出包括 `evaluation.json`、`algorithm_run_manifest.json`、`testing_record_perception_labeled.csv` 和对应 JSON。报告分别列出二维候选指标与最终确认指标，并记录候选到确认耗时、单帧处理耗时、输出频率、三维定位覆盖率与误差。算法标签、Git 提交和参数文件 SHA-256 用于证明各轮回放只改变声明的控制变量。传给 `--parameter-file` 的文件必须与启动检测节点时的 `perception_parameter_file` 完全一致；启动器会把该分组配置严格展开为实际 ROS 参数，未知键会直接中止启动。禁止将“需复查”候选写成已确认危险源。

同一 rosbag 测试其他算法或参数时，使用新的输出目录和 `--algorithm-label`。当前每轮只能传入一个实际启动检测节点的 `--parameter-file`，不得把说明文档等无关文件计入参数快照，也不得覆盖上一轮结果。

完成至少两轮受控回放后统一生成横向表：

```bash
python3 scripts/compare_perception_replay_runs.py \
  --run-dir reports/perception/official_random/replay_seed_20260803_baseline \
  --run-dir reports/perception/official_random/replay_seed_20260803_candidate \
  --output-dir reports/perception/official_random/replay_seed_20260803_comparison
```

比较器只接受源 rosbag 内容指纹、SEED 和人工标注文件 SHA-256 完全一致的实验，并核对评估标签、参数哈希、Git 提交与实际回放清单；回放或评估任一阶段存在未提交代码都会拒绝比较。即使目录路径相同，只要 bag 内容改变也拒绝比较。输出 `replay_comparison.json` 和 `replay_comparison.csv`；其中排序仅用于算法回归审阅，不等同于官方总分。

同一批算法完成至少三个 SEED 的逐场景比较后，再生成跨场景总表。每个 SEED 必须包含完全相同的算法标签、参数哈希和 Git 提交；不得漏跑失败场景或在不同 SEED 间更换版本。

```bash
python3 scripts/compare_perception_replay_campaign.py \
  --run-dir reports/perception/official_random/replay_seed_20260803_baseline \
  --run-dir reports/perception/official_random/replay_seed_20260803_candidate \
  --run-dir reports/perception/official_random/replay_seed_20260804_baseline \
  --run-dir reports/perception/official_random/replay_seed_20260804_candidate \
  --run-dir reports/perception/official_random/replay_seed_20260805_baseline \
  --run-dir reports/perception/official_random/replay_seed_20260805_candidate \
  --output-dir reports/perception/official_random/replay_campaign_20260805
```

输出 `replay_campaign_comparison.json` 和 `replay_campaign_comparison.csv`，记录跨 SEED 微平均召回率/F1、定位误差、确认时延、处理耗时、输出频率及各项最差场景值。该表用于选择稳定方案，不替代官方总分。

## 6. 收尾

先在键盘终端按 `K`，再依次结束录包、键盘节点和业务 launch。确认没有成员继续使用后，由平台管理员按平台手册执行 `auto_docker.sh down`；该命令会先停止适配器，再停止容器。
