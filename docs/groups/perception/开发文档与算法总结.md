## 1. 项目概述

感知组负责 HazardWalker 机器狗在灾害场景中的红色球体危险源检测、定位、跟踪和确认。核心流程为：RGB-D 图像采集 → HSV 红球检测 → 三维定位 → 多帧跟踪确认 → 危险源结果输出。

## 2. 已解决的问题

### 2.1 红色球体检测

| 问题 | 解决方案 | 状态 |
|---|---|---|
| 如何在无 GPU 环境下快速检出红色球体 | 采用 OpenCV HSV 颜色空间阈值 + 形态学处理，无需训练数据和 GPU | ✅ 已解决 |
| 如何过滤红色非球体误检（方块、长条等） | 引入圆形度(circularity)、长宽比(aspect_ratio)、轮廓占比(extent)三重形状筛选 | ✅ 已解决 |
| 如何分离粘连的多个红球 | 距离变换(Distance Transform) + 分水岭(Watershed)算法，检测凹缺陷深度后拆分 | ✅ 已解决 |
| 如何处理暗红/低饱和度红色噪声 | HSV 双阈值区间：H∈[0,10]∪[170,180], S≥80, V≥80 | ✅ 已解决 |
| 如何处理不同程度的遮挡 | 15%–35% 可见产生黄色复查候选；45% 以上产生严格候选；5%–10% 由左右括号扫描恢复 | ✅ 已解决 |
| 如何处理红色跨越 hue 圆周边界 | 使用两段 hue 区间：H∈[0,10] 和 H∈[170,180] | ✅ 已解决 |

### 2.2 动态识别

| 问题 | 解决方案 | 状态 |
|---|---|---|
| 如何记录运动中的检测结果 | `dynamic_detection_recorder_node.py`：订阅图像、里程计和检测结果，写入逐帧记录 | ✅ 已解决 |
| 如何避免运动中伪造多视角 | 相机运动期间冻结轨迹证据；平移>0.002m 或偏航>0.3°不视为新视角 | ✅ 已解决 |
| 如何保证一个停靠周期一个view_id | 稳定停靠周期只锁定一个 view_id，避免慢速运动或量化抖动伪造多视角 | ✅ 已解决 |

### 2.3 主动视角

| 问题 | 解决方案 | 状态 |
|---|---|---|
| 单视角无法区分球体和圆柱端面 | 触发主动侧视复查，非直接确认；请求导航层横向移动获取侧面视角 | ✅ 已解决 |
| 如何决定移动方向 | `active_view_policy.py`：根据候选框贴边、遮挡、深度形状，输出靠近/横移/转向/调俯仰建议 | ✅ 已解决 |
| 如何确保真正侧视 | 要求相机到同一目标的水平视线跨度至少 25°；仅在正面前后靠近不算独立视角 | ✅ 已解决 |
| 平面深度候选如何标记 | 圆柱/圆锥/圆盘端面标记为 `needs_reobservation`，不进入 confirmed | ✅ 已解决 |

### 2.4 多帧确认

| 问题 | 解决方案 | 状态 |
|---|---|---|
| 单帧误检导致假阳性 | 要求 ≥3 次观测 + ≥2 个离散视角 + 水平视线跨度 ≥25° 才确认 | ✅ 已解决 |
| 同一红球多次上报 | 三维欧氏距离最近邻合并（merge_distance_m=0.5m） | ✅ 已解决 |
| 目标消失后残留轨迹 | missed_count 达到阈值后标记为 rejected | ✅ 已解决 |
| 同一连通域多圆误报（哑铃/双叶） | 拆分候选全部标记 `may_be_merged` + `requires_reobservation`，不能在同一视角直接确认 | ✅ 已解决 |
| 轨迹深度形状一致性 | 联合检查三维位置一致性、表观直径变异(CV≤0.35)、最差视角长宽比(≥0.88)、深度曲率变异 | ✅ 已解决 |

### 2.5 三维定位

| 问题 | 解决方案 | 状态 |
|---|---|---|
| 2D bbox 到世界坐标转换 | bbox 中心像素 → CameraInfo 内参反投影 → ROI 深度中位数 → 刚体变换 → 世界坐标 | ✅ 已解决 |
| 球体中心到球面深度补偿 | 使用 bbox 投影半径反推球心深度（球面投影几何），非球形目标可选关闭 | ✅ 已解决 |
| 远距离过补偿 | 贴边/遮挡/过小候选自动退回保守深度补偿 | ✅ 已解决 |
| 深度对齐和 TF 不可用 | 仅发布 2D 结果，不伪造三维坐标 | ✅ 已解决 |

## 3. 使用的算法

### 3.1 红球检测算法（HSV + OpenCV 形状筛选）

```
输入: RGB/BGR 图像
  │
  ├─ Step 1: HSV 颜色空间转换
  │   └─ 使用 OpenCV cvtColor() 转换
  │
  ├─ Step 2: 红色阈值分割
  │   ├─ H ∈ [0, 10] ∪ [170, 180]  (红色跨 hue 边界)
  │   ├─ S ≥ 80                     (排除低饱和度)
  │   └─ V ≥ 80                     (排除暗红)
  │
  ├─ Step 3: 形态学去噪
  │   └─ 开运算 (MORPH_OPEN) + 闭运算 (MORPH_CLOSE)
  │
  ├─ Step 4: 轮廓提取
  │   └─ cv2.findContours() → 连通域列表
  │
  ├─ Step 5: 粘连分离（可选）
  │   ├─ 凹缺陷深度检查 (cv2.convexityDefects)
  │   ├─ 距离变换 (cv2.distanceTransform)
  │   └─ 分水岭 (cv2.watershed)
  │
  ├─ Step 6: 形状筛选
  │   ├─ 面积 ≥ 200 px (严格) / ≥ 20 px (宽松黄色候选)
  │   ├─ 圆形度 ≥ 0.65 (严格) / ≥ 0.30 (宽松)
  │   ├─ 长宽比 ∈ [0.45, 1/0.45]
  │   └─ extent ∈ [0.35, 0.92]
  │
  └─ 输出: RedBallDetection2D 列表（按置信度降序）
```

**参数配置** (`config/perception.yaml`):
- `lower_red_1: [0, 80, 80]`, `upper_red_1: [10, 255, 255]`
- `lower_red_2: [170, 80, 80]`, `upper_red_2: [180, 255, 255]`
- `min_area_px: 80`, `min_confidence: 0.5`

### 3.2 三维定位算法

```
输入: bbox, CameraInfo K, 深度图, TF(camera_link→output_frame)
  │
  ├─ Step 1: bbox 中心像素坐标
  │   └─ cx = (x_min + x_max) / 2, cy = (y_min + y_max) / 2
  │
  ├─ Step 2: 内参反投影（方向向量）
  │   └─ [dx, dy, 1] = K⁻¹ × [cx, cy, 1]ᵀ
  │
  ├─ Step 3: bbox ROI 深度采样
  │   └─ 取 ROI 区域深度中位数（排除 0/NaN/Inf）
  │
  ├─ Step 4: 球面深度补偿（可选）
  │   ├─ 根据 bbox 投影半径和已知球体半径反推球心深度
  │   └─ depth_corrected = depth_measured + sphere_radius × cos(θ)
  │
  ├─ Step 5: 相机坐标系三维坐标
  │   └─ P_cam = depth × [dx, dy, 1]
  │
  ├─ Step 6: 刚体变换到输出坐标系
  │   └─ P_world = T_cam_to_world × P_cam
  │
  └─ 输出: HazardObservation(position, confidence, stamp_sec, ...)
```

### 3.3 多帧跟踪与确认算法

```
输入: 每帧 HazardObservation 列表
  │
  ├─ Step 1: 距离最近邻匹配
  │   └─ 当前观测与已有轨迹按 merge_distance_m (0.5m) 欧氏距离匹配
  │
  ├─ Step 2: 轨迹更新
  │   ├─ 匹配成功 → 加权平均更新位置，observation_count++
  │   ├─ 匹配失败 → 创建新轨迹 (status='tentative')
  │   └─ 旧轨迹无匹配 → missed_count++
  │
  ├─ Step 3: 视角管理
  │   ├─ 运动帧(平移>0.002m 或 偏航>0.3°) → 冻结证据，不累加
  │   ├─ 稳定帧 → 锁定 view_id
  │   └─ 同一 view_id 不可重复计数
  │
  ├─ Step 4: 多视角交叉验证
  │   ├─ 水平视线跨度 ≥ 25°
  │   ├─ 表观直径变异系数 ≤ 0.35
  │   ├─ 最差视角长宽比 ≥ 0.88
  │   ├─ 深度曲率中位数 ∈ [0.10, 0.30]
  │   └─ 深度平面候选 → needs_reobservation
  │
  ├─ Step 5: 状态转换
  │   ├─ observation_count ≥ 3 + 多视角验证 → confirmed
  │   ├─ missed_count ≥ 10 → rejected
  │   └─ merged_split 候选 → 保持 tentative/needs_reobservation
  │
  └─ 输出: HazardTrack 列表（含 status, 多视角证据）
```

### 3.4 主动视角策略算法

```
输入: 当前候选列表 + 相机位姿
  │
  ├─ Step 1: 候选评估
  │   ├─ 贴边检测：bbox 边缘接近图像边界
  │   ├─ 深度形状分类：spherical / flat / unknown
  │   ├─ 遮挡等级：按红色像素比估计
  │   └─ 置信度阈值
  │
  ├─ Step 2: 动作生成
  │   ├─ 平面深度 (flat) → move_left + move_right（括号扫描）
  │   ├─ 局部遮挡 → move_forward（靠近）
  │   ├─ 贴边 → 反方向移动
  │   ├─ 粘连候选 → move_left + move_right（最大视差）
  │   └─ 多球密集 → 两侧最大视差复查
  │
  ├─ Step 3: Waypoint 生成
  │   ├─ 分段圆弧路径
  │   ├─ 目标朝向角度
  │   └─ 可被导航层逐段避障执行
  │
  └─ 输出: 发布到 /hazardwalker/perception/reobservation_request
```

### 3.5 动态检测记录算法

```
输入: 感知输出流 + 里程计流
  │
  ├─ Step 1: 逐帧记录
  │   ├─ frames.jsonl: 候选位置、置信度、确认状态、动作建议
  │   ├─ 精选截图: 按最小时间间隔保存证据帧
  │   └─ 位姿快照: 每次停靠记录机器人世界位姿
  │
  ├─ Step 2: 实验摘要
  │   ├─ summary.json: 动态帧数、候选数、确认数、平均置信度
  │   └─ testing_record_perception.csv/json: 测试组标准格式
  │
  └─ 输出目录: reports/perception/simulation/3d_native/<suite_name>/
```

### 3.6 房间搜索策略

**固定巡检模式**: 按预定义路径遍历房间
**主动模式 (A/B 测试)**: 根据感知反馈动态调整搜索路径
- A 策略: 固定路径覆盖
- B 策略: 感知驱动自适应搜索

## 4. 核心架构设计

### 4.1 数据流

```
/hw/camera/image_raw ──┐
/hw/camera/camera_info─┤
/hw/camera/depth_image ─┤
/tf ───────────────────┤
/hw/odom ──────────────┤
                        ▼
              hsv_detector_node
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
  red_ball_detector  localize_hazard  track_hazards
  (2D检测)           (三维定位)       (多帧确认)
        │               │               │
        └───────────────┴───────────────┘
                        │
                        ▼
         /hw/perception/hazard_detections  (三维)
         /hw/perception/detections_2d      (二维降级)
         /hw/perception/debug_image        (调试)
```

### 4.2 可扩展检测后端

```
DetectionBackend (接口)
  ├─ HsvOpenCvDetectionBackend   ← 当前默认
  ├─ [预留] YoloBackend          ← 深度学习检测
  ├─ [预留] SegmentBackend       ← 实例分割
  └─ [预留] RgbdBackend          ← RGB-D 一致性过滤
```

### 4.3 两层候选机制

```
图像检测
  ├─ 严格候选 (strict)
  │   ├─ 面积 ≥200 px, 圆度 ≥0.65
  │   ├─ 允许进入三维 tracking
  │   └─ 可参与多帧确认 → confirmed
  │
  └─ 宽松候选 (reobserve)
      ├─ 面积 ≥20 px, 圆度 ≥0.30
      ├─ requires_reobservation = true
      ├─ 不能单帧确认
      └─ 触发主动换视角复查
```

## 5. 关键参数速查

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_area_px` (严格) | 200 px | 进入严格候选的最小红色像素数 |
| `min_circularity` (严格) | 0.65 | 进入严格候选的最小圆形度 |
| `min_aspect_ratio` | 0.45 | bbox 短边/长边最小比例 |
| `min_extent` / `max_extent` | 0.35 / 0.92 | 轮廓面积/bbox面积范围 |
| `merge_distance_m` | 0.5 | 三维轨迹合并距离阈值 |
| `confirm_observation_count` | 3 | 确认所需最少观测次数 |
| `reject_after_missed_count` | 10 | 连续丢失次数后拒绝 |
| `min_distinct_views` | 2 | 确认所需最少离散视角 |
| `min_horizontal_span_deg` | 25° | 确认所需最少水平视线跨度 |
| `max_apparent_diameter_cv` | 0.35 | 表观直径变异系数上限 |
| `min_multiview_aspect_ratio` | 0.88 | 多视角最差长宽比下限 |
| `max_detection_range_m` | 20.0 | 最远检测距离 |
| `sphere_radius_m` (官方) | 0.15 | 标准红球半径 |
