## 模块一：红球检测（Red Ball Detection）

### 1.1 模块概述

红球检测是感知组的入口模块，负责从 RGB 图像中检出红色球体候选区域。当前采用 OpenCV HSV 颜色空间阈值 + 形态学处理 + 形状筛选的经典计算机视觉方案，无需 GPU 和训练数据，可立即部署。

### 1.2 核心算法

**HSV 红色阈值分割**：
- 红色在 HSV 色相环上跨越 0°/360° 边界，需两段区间检测
- 区间1: H ∈ [0, 10], S ≥ 80, V ≥ 80
- 区间2: H ∈ [170, 180], S ≥ 80, V ≥ 80

**形状筛选（四重过滤）**：
1. **圆形度** (circularity = 4πA/P²)：严格 ≥0.65，区分球体和方块
2. **长宽比** (aspect_ratio)：≥0.45，过滤细长红色物体
3. **轮廓占比** (extent = contour_area/bbox_area)：∈[0.35, 0.92]，过滤空心或实心矩形
4. **面积** (min_area_px)：严格 ≥200 px，过滤噪声和远距离微小目标

**粘连分离**：
- 凹缺陷深度检查（convexityDefects）
- 距离变换（distanceTransform）
- 分水岭分割（watershed）
- 拆分候选标记 `may_be_merged` + `requires_reobservation`

### 1.3 两层候选输出

| 层级 | 面积阈值 | 圆形度阈值 | 用途 |
|---|---:|---:|---|
| 严格候选 (strict) | ≥200 px | ≥0.65 | 进入三维 tracking，可多帧确认 |
| 黄色候选 (reobserve) | ≥20 px | ≥0.30 | 触发主动换视角，不能单帧确认 |

### 1.4 核心文件

- `red_ball_detector.py` — 纯函数检测管线（27798 行）
- `hsv_detector_node.py` — ROS2 节点，连接相机和检测器
- `config/perception.yaml` — 检测参数配置

### 1.5 验收标准

| 测试场景 | 预期 | 实际 | 状态 |
|---|---|---|---|
| 正常红球检出 | ✓ 检出 | ✓ 检出 | ✅ |
| 暗红过滤 (V<80) | ✗ 不检出 | ✗ 不检出 | ✅ |
| 低饱和度过滤 (S<80) | ✗ 不检出 | ✗ 不检出 | ✅ |
| 红色方块过滤 | ✗ 不检出 | ✗ 不检出 | ✅ |
| 红色三角形过滤 | ✗ 不检出 | ✗ 不检出 | ✅ |

### 1.6 局限性

- 严重依赖固定 HSV 阈值，对光照变化敏感

- 单视角无法区分球体和圆柱/圆盘端面（需多视角确认）

## 模块二：动态识别（Dynamic Recognition）

### 2.1 模块概述

动态识别模块负责在机器人运动过程中连续记录检测结果，区分"真正在运动"和"静止拍摄多帧"。它与多帧确认模块协同工作：运动期间冻结轨迹累计，稳定停靠后才累加新视角证据。

### 2.2 核心机制

**运动检测与冻结**：
- 平移 > 0.002 m 或偏航 > 0.3° → 当前帧标记为"运动中"，轨迹证据冻结
- 稳定停靠 → 锁定一个 view_id，该停靠周期内所有帧共享同一 view_id
- 避免慢速运动或传感器量化抖动伪造多视角

**动态帧记录**：
- `frames.jsonl`：每帧的候选列表、位姿、确认状态、动作建议
- `selected_images/`：按最小时间间隔保存证据帧
- `summary.json`：动态帧数、候选数、确认数、平均置信度

**动态特征分析**：
- 表观直径随距离变化（接近时变大，远离时变小）
- 深度曲率在不同视角的一致性
- 长宽比在不同视角的稳定性（球体始终接近 1:1）

### 2.3 核心文件

- `dynamic_detection_recorder_node.py` — ROS2 动态记录节点
- `dynamic_detection_records.py` — 动态记录数据结构和汇总逻辑

### 2.4 输出产物

```
reports/perception/simulation/3d_native/<suite_name>/
├── frames.jsonl           # 逐帧检测记录
├── selected_images/       # 证据帧截图
├── summary.json           # 实验摘要
├── cases.csv / cases.json # 每例的详细数据
└── 拼图 / 标注图           # 可视化产物
```

### 2.5 验收标准

- 运动中不累加新的 confirmed 计数
- 同一个稳定停靠周期只产生一个 view_id
- ROS2 shutdown 信号下正常收尾，不丢失已记录数据
- 测试组 CSV/JSON 格式与集成测试组模板一致

## 模块三：主动视角（Active Viewpoint）

### 3.1 模块概述

主动视角模块解决单视角几何不可辨识性问题：圆柱端面、圆盘端面、圆锥底面等在正面视角下投影为圆形，仅靠单一图像无法与球体区分。模块根据候选框的特征（贴边、遮挡、深度形状）生成主动复查建议，但不直接控制机器人运动。

### 3.2 为什么需要主动视角

| 单视角混淆物 | 正面投影 | 需要侧视确认 |
|---|---|---|
| 圆柱端面 | 圆形 | ✓ 侧面显示为矩形 |
| 圆盘端面 | 圆形 | ✓ 侧面显示为薄矩形 |
| 圆锥底面 | 圆形 | ✓ 侧面显示为三角形 |
| 近圆椭球 | 圆形 | ✓ 侧面长宽比变化 |
| 胶囊端面 | 圆形 | ✓ 侧面长宽比变化 |

### 3.3 核心算法

**候选评估**（`active_view_policy.py`）：
1. 贴边检测 → bbox 边缘接近图像边界
2. 深度形状分类 → spherical / flat / unknown
3. 遮挡等级 → 按红色像素比估计
4. 置信度 → 低于阈值触发复查

**动作生成策略**：

| 候选状态 | 推荐动作 | 优先级 |
|---|---|---|
| 平面深度 (flat) | move_left + move_right（括号扫描） | 高 |
| 局部遮挡 (<45%) | move_forward（靠近） | 中 |
| 贴边候选 | 反方向平移 | 高 |
| 粘连候选 (merged_split) | move_left + move_right（最大视差） | 高 |
| 多球密集 | 两侧最大视差复查 | 高 |
| 低置信度 | 旋转/调俯仰复查 | 低 |

**Waypoint 生成**（`active_view_geometry.py`）：
- 分段圆弧路径（可由导航层逐段避障执行）
- 目标朝向角度
- 侧视位移距离计算

### 3.4 关键约束

- 绝对不直接发布 `/cmd_vel`
- 仅发布 `/hazardwalker/perception/reobservation_request`
- 最终确认要求水平视线跨度 ≥ 25°
- 仅在正面前后靠近不能确认，必须取得侧面复查

### 3.5 核心文件

- `active_view_policy.py` — 主动视角策略决策
- `active_view_geometry.py` — 视角几何计算
- `room_search_policy.py` — 房间级搜索策略（固定 vs 主动 A/B）

### 3.6 验收标准

- 圆柱端面/圆盘端面在初始正面视角下标记为 `needs_reobservation`
- 15%–35% 可见球体产生黄色候选并触发复查
- 运动后能成功恢复受控目标
- 不向 `/cmd_vel` 直接发布速度命令

## 模块四：多帧确认（Multi-frame Confirmation）

### 4.1 模块概述

多帧确认模块将单帧的三维观测合并为稳定的危险源轨迹，通过多视角交叉验证消除单帧误检。只有满足全部条件的轨迹才会被标记为 confirmed 并写入最终危险源结果。

### 4.2 核心算法

**轨迹生命周期**：
```
tentative → collecting_views → confirmed
                               → rejected (missed_count 超限)
```

**确认条件（全部必须满足）**：
1. `observation_count ≥ 3`
2. 至少 2 个离散相机视角（基于水平位置和朝向量化）
3. 相机到同一目标的水平视线跨度 ≥ 25°
4. 表观直径变异系数 ≤ 0.35（排除非球形目标）
5. 最差视角长宽比 ≥ 0.88（排除椭球/圆柱端面）
6. 深度曲率中位数 ∈ [0.10, 0.30]（排除平面和极端曲面）
7. 非 `needs_reobservation` 状态

**反证条件（任一满足则拒绝）**：
- 连续 `missed_count ≥ 10`
- 平面深度（flat）且未获得侧面确认
- 粘连拆分候选在不同视角未形成独立轮廓

**三维位置一致性检验**：
- 同一轨迹的不同视角观测在三维空间中的位置偏差 < merge_distance_m
- 加权平均更新位置（新观测权重更高）

### 4.3 核心文件

- `track_hazards.py` — 多帧跟踪与确认纯函数（23537 行）
- `config/perception.yaml` — tracking 参数

### 4.4 关键参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| confirm_observation_count | 3 | 最少观测次数 |
| reject_after_missed_count | 10 | 连续丢失次数后拒绝 |
| merge_distance_m | 0.5 | 三维合并距离 |
| min_distinct_views | 2 | 最少离散视角数 |
| min_horizontal_span_deg | 25° | 最少水平视线跨度 |
| max_apparent_diameter_cv | 0.35 | 最大表观直径变异系数 |
| min_multiview_aspect_ratio | 0.88 | 多视角最差长宽比 |

### 4.5 验收标准

- 单帧红色圆形不进入 confirmed
- 哑铃/双叶/三叶等拆分候选不直接确认
- 平面深度候选标记为 needs_reobservation
- 丢失目标正确进入 rejected
- 122 项离线测试全通过

## 模块五：三维定位（3D Localization）

### 5.1 模块概述

三维定位模块将 2D 检测框转换为世界坐标系中的三维坐标，为导航、决策和多帧确认提供空间信息。当前实现基于 RGB-D 传感器（RGB 相机 + 深度图 + TF 变换）。

### 5.2 核心算法

**定位流水线**：
```
2D bbox → 中心像素坐标
  → CameraInfo K 内参反投影（方向向量）
  → bbox ROI 深度图中位数（距离）
  → 球面深度补偿（球心 vs 球面）
  → 相机坐标系三维坐标
  → TF 刚体变换（camera_link → output_frame）
  → 世界/start 坐标系位置
```

**球面深度补偿**：
- 深度图返回的是球面前沿距离
- 对于标准球体（radius=0.15m），需补偿到球心
- 使用 bbox 投影半径反推球心深度的几何关系
- 非球形目标可设置 `sphere_radius_m=0.0` 关闭

**降级处理**：
- 深度图不可用 → 只输出 2D 结果，不伪造三维坐标
- TF 不可用 → 只输出 2D 结果
- 贴边/遮挡/过小候选 → 自动退回保守深度补偿
- TF 时间戳偏差 → 回退到最新 TF（allow_latest_tf_fallback）

### 5.3 精度表现

**复杂环境三维定位套件（8 例，32 点）**：

| 指标 | 数值 |
|---|---:|
| 真值点匹配率 | 32/32 (100%) |
| 加权平均误差 | 0.0306 m |
| 最大误差 | 0.0995 m |
| 验收上限 | 0.15 m |

### 5.4 误差来源分析

| 误差来源 | 影响程度 | 缓解措施 |
|---|---|---|
| RGB bbox 中心不准 | 中 | 使用 bbox 中心而非角点 |
| 深度图边缘噪声 | 高 | 使用中位数而非均值 |
| 相机内参标定误差 | 低 | 依赖官方 SimEnv 标定 |
| TF 变换时延 | 中 | allow_latest_tf_fallback |
| 球面补偿假设 | 中 | 贴边/遮挡自动退回保守补偿 |

### 5.5 核心文件

- `localize_hazard.py` — 三维定位纯函数（12295 行）
- `hsv_detector_node.py` — 节点中调用三维定位

### 5.6 验收标准

- 32/32 真值点全部匹配
- 加权平均误差 < 0.15 m（实际 0.0306 m）✅
- 最大误差 < 0.15 m（实际 0.0995 m）✅
- 深度不可用时正确降级到 2D-only 输出
- 9 项离线测试全通过 ✅
